## What this shows

- whether a real model can produce a graded submission on a deliberately non-standard task, and at what measured cost (wall clock, and oracle queries where the access mode counts them) and self-reported cost (tokens, tool calls);
- whether the protected profile changes either, with the variance the repetitions actually exhibit;
- the probe's artifact size difference between the two profiles.

## What this does **not** show

- **No protection effect is measurable in this run at all.** The agent's workspace held an oracle shim whose behaviour is identical in every artifact profile; it could not inspect the artifact, so levels 1–3 presented exactly the same information as the baseline. A level-vs-baseline difference here is noise, not evidence. Protection comparisons need `--access binary`.

- **`packed-record-v1` is not calibrated to a measurable baseline** for this agent and access mode: the baseline never passed there, or there is no record. Neither a success-rate nor a cost delta is interpretable on such a task — the agent fails for reasons that have nothing to do with the protection.

- **No effectiveness claim.** N is small and only one task and one model were run; the pass column describes what this agent could do, not what a protection prevented.
- No claim about other attacker classes or larger models.
- Token figures include an estimate for calls aborted by the reasoning watchdog (`tokens_source` and `aborted_tokens_estimate` in the JSONL mark the share).
- Model and relay drift: rerunning later may produce different costs for the same model id.
