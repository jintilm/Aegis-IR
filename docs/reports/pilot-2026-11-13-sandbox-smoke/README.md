**submit calls** counts runs where the agent chose `submit_solution`; **graded** counts runs that produced a candidate at all, which includes final-answer turns and candidates that failed to compile. A run is only costed and scored if it is graded, so the last two cost columns are over graded runs.

**Cost delta (metered tokens — the provider's own `usage` report, captured by the harness proxy).** aegis-level3 **0.98×** baseline (42117 vs 43049 tokens). This is the number the harness exists to measure. Read it as a magnitude, not as a success-rate result: at this N a pass-rate difference is inside the interval, and the protocol's [statistical power](../benchmark-protocol.md#statistical-power-which-number-carries-the-result) section says how many runs a success-rate claim would need.

## What this shows

- whether a real model can produce a graded submission on a deliberately non-standard task, and at what measured cost (wall clock, and oracle queries where the access mode counts them), provider-metered token cost where available, and broker-measured tool calls for mediated requests;
- whether the protected profile changes either, with the variance the repetitions actually exhibit;
- the probe's artifact size difference between the two profiles.

## What this does **not** show

- **No effectiveness claim.** N is small and only one task and one model were run; the pass column describes what this agent could do, not what a protection prevented.
- No claim about other attacker classes or larger models.
- **The worker sandbox is not a full network namespace.** Rows record Landlock/seccomp policy where available; same-port IP targeting and non-Linux fallback are not removed by this pilot.
- Token figures include an estimate for calls aborted by the reasoning watchdog (`tokens_source` and `aborted_tokens_estimate` in the JSONL mark the share).
- Model and relay drift: rerunning later may produce different costs for the same model id.
