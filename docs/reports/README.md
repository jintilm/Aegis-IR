# Reports

Machine-generated evidence, one directory per run. Each directory carries a
`README.md` written by the generator explaining what the numbers show and —
more importantly for this project — what they do not.

Rules:

- Reports are generated by a script in `scripts/`, never hand-edited. If a
  number is wrong, fix the generator and regenerate.
- Every report names the commit it was produced from. If the working tree was
  dirty at generation time, the report says so; do not silently clean that up.
- A report may only be cited from the claims ledger
  ([`../claims-ledger.md`](../claims-ledger.md)) once its claims are written
  in the ledger's wording.
- "Validation" reports (offline test doubles, self-checks) are reproducible
  but are **not** effectiveness evidence. They must say so in their own
  README, because that is the line a reader will otherwise misread.
- A binary-recovery report must state its **access mode**. Under `oracle`
  access the agent sees a shim that is identical in every artifact profile, so
  any level-vs-baseline delta in such a report is zero by construction and
  cannot be cited; only `binary` access can measure a protection effect.
- A protection comparison must also name the task's **calibration**. A task
  whose unprotected baseline sits at the floor or the ceiling cannot show an
  effect; the report warns when that is the case.

Still missing, and therefore unclaimed: any effectiveness measurement, any
statement about attacker difficulty, and any success-rate effect. The pilots are
listed above to document what the pipeline can and cannot measure; none of them
is evidence that protection changed an outcome, and none may be cited as such.
What they do establish is a **cost** magnitude: level 3 costs about twice the
tokens of the baseline under `binary` access, unconditionally across graded
runs, in three independent runs at one step budget.

The N=5 runs also correct the N=2 pilot that precedes them, which is the reason
all are kept: a two-run cell cannot distinguish a protection effect from the
agent's own variance, and these tasks are bimodal — the agent either solves one
or produces almost nothing. Earlier cost figures were conditioned on submission;
the newest run gives every non-infrastructure run a ledger, which is why its
ratio is unconditional.
