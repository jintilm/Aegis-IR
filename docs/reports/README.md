# Reports

Machine-generated evidence, one directory per run. Each directory carries a
`README.md` written by the generator explaining what the numbers show and —
more importantly for this project — what they do not.

Rules:

- Reports are generated by a script in `scripts/`, never hand-edited. If a
  number is wrong, fix the generator and regenerate.
- Every report names the commit it was produced from. If the working tree was
  dirty at generation time, the report says so; do not silently clean that up.
- A report may only be cited from the claims ledger
  ([`../claims-ledger.md`](../claims-ledger.md)) once its claims are written
  in the ledger's wording.
- "Validation" reports (offline test doubles, self-checks) are reproducible
  but are **not** effectiveness evidence. They must say so in their own
  README, because that is the line a reader will otherwise misread.

Still missing, and therefore unclaimed: any effectiveness measurement, any
adversarial cost-delta number, any statement about attacker difficulty. The
pilot is listed above to document that the pipeline works against a real
model; it is not evidence that protection changed anything, and it must not be
cited as such.

A task on which the unprotected baseline already fails cannot demonstrate a
protection effect. The next experiment must therefore begin with a
task/model/budget combination where the baseline succeeds at a rate the
measurement can move.
